# Windows desktop support

Ship a Windows x64 installer that records the selected microphone and default speaker/output mix, checkpoints/transcribes minute sections during capture, creates editable notes, stores the API key in Windows Credential Manager, and preserves the existing macOS application. Windows 11 is the primary supported OS; Windows 10 22H2 is a compatibility target, not a current OS-security recommendation. Existing automatic language detection, speaker labels, questions, notes, retry and local storage are shared.

Use existing `windows` 0.61 bindings for WASAPI shared capture, native format conversion to mono 16 kHz PCM16, and sleep prevention. Capture and disk finalization run independently through a bounded queue; overflow/discontinuity/device failure must be visible. Devices are selected when recording begins; automatic route switching is not promised in this port. System capture covers the default output endpoint, including Edge audio routed there. A new dependency on FFmpeg, Electron, an audio daemon or a wrapper framework is unnecessary.

Write real WAV files on Windows, retaining native AAC on macOS. Persist `audioFormat` (m4a/wav) with historical default m4a. Derive exact owned paths from this field and maintain all existing containment/link checks. Each WAV minute is about 1.92 MB; even a five-minute retry section fits the 24 MB upload guard. A constrained stdlib PCM reader/writer validates headers, lengths, frame alignment and ranges. Successful finalization flushes and syncs before publishing a section; text checkpoints commit before audio deletion. Windows durable replacement must preserve the prior JSON on failure.

Keep the existing recorder start/rotate/health/stop interface. `audio::wav::Writer::create(path, sample_rate)`, `write_pcm(&[u8])`, `frames()` and consuming `finish()` own the Windows file format. `audio::wav::inspect_bytes` supplies upload validation; `audio::inspect` and `audio::write_chunk` dispatch WAV independently of the host OS. Retained Mac AAC processing remains a Mac capability.

Windows NSIS installs per-user with a compatible WebView2 runtime. Windows CI runs Rust/frontend tests, native credential persistence, installer installation/launch checks and packaging. A single release publisher waits for both Windows EXE and existing Mac DMG artifacts. No Mac installation/restart during this work. Automated CI does not prove microphone/loopback quality on a physical Windows laptop; state that limit explicitly.
