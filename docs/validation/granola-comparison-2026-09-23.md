# Granola comparison and implementation acceptance — 23 September 2026

## Evidence and scope

Primary reference: the installed Granola macOS app, inspected through native accessibility and screenshots on this date. The account displays **Business Trial, 30 days left**. Availability on that account is not evidence of free-plan availability. No purchase, connector authorization, sharing, settings change, or user-note import was performed. Experiments used a clearly labeled synthetic Atlas planning note and Granola's built-in demo meeting. Both transcription sessions were stopped. The first New note unexpectedly began transcription immediately; that brief capture is not a controlled acoustic test.

Secondary reference: [official documentation evidence matrix](granola-official-reference-2026-09-23.md), which labels documentation-only claims and account/platform restrictions. Screenshots containing account details were not copied into the repository. This report describes observations without copying proprietary assets or implementation.

Our baseline is source checkpoint `c3c65a2` plus ongoing Windows validation on PR23. The installed Meeting Notes remains v0.4.5 until a later verified installation receipt says otherwise. Findings below are source-derived unless specifically marked as exercised.

## Selected implementation acceptance

1. **Live recovery:** a synthetic outage beyond all fast retries recovers before recording ends; each successful section uploads once; audio remains until transcript checkpoint succeeds; invalid credentials stay paused; Stop interrupts a long retry delay promptly and uses a finite final retry budget.
2. **Safe notes:** first and repeated successful enhancement keep the exact immediately previous document, including intentional blanks; both document and backup persist atomically; failed generation/storage cannot erase either; concurrent typing wins; Restore swaps the two documents, rejects stale expectations/active processing, and never changes metadata/transcript. This is one reversible previous version, not unlimited history.
3. **Conversation recovery:** meeting, folder and all-meeting scopes stay separate; navigation during a request does not cancel/discard its result; drafts/full answers/citations survive restart; an interrupted request is explicitly retryable and is never automatically rebilled; deleted meeting/transcript data is removed from stored conversations; storage failures remain visible without dropping current in-memory text. Only request context is bounded, never silently displayed history.
4. **Usable UI:** verify normal and minimum native widths, keyboard/IME and multiline input, long answers, discreet expandable sources, source navigation and return, copy, failure/retry, draft during pending, no-key/empty states and reduced-motion behavior. Preserve parchment/olive/editorial identity and add no animation framework.
5. **Windows release gate:** native Windows test and build results, Credential Manager test, per-user installer launch/reinstall/uninstall checks preserving synthetic files, and dual-platform release artifacts. Physical Windows microphone, system loopback, Bluetooth, device removal/switching, sleep/wake and Edge playback remain explicitly unverified without hardware.

## Deliberate limits and follow-on work

Granola crash/offline recovery, actual long recordings, collaboration, paid integrations and speaker identification were not experimentally stressed. Onboarding was inspected from an already signed-in account, not by resetting credentials or permissions. No outage was induced against the user's actual Granola account. These are unverified, not missing capabilities.

Our known follow-ons include isolating corrupt individual session files during bootstrap, querying useful saved notes in draft/failed sessions, context selection beyond the latest 20 completed meetings / 200 KB request limit, richer speaker identity controls, and optional templates. None warrants hiding this release's data-loss risks behind additional interface features.
