# Granola official reference — 23 September 2026

This is a documentation supplement to the separate installed-app inspection. **Nothing here is claimed as observed desktop behavior.** Account availability, actual interactions, performance, and recovery must be established in the installed app. Sources were read on 2026-09-23; links point to official Granola documentation unless identified as an official product announcement. No user notes, recordings, credentials, or settings were accessed for this research.

## Evidence matrix

| --- | --- | --- |
| Start and monitor transcription | Opening a started calendar note, clicking a reminder, or creating a New Note initiates capture. Opening an upcoming note schedules capture for its start. Green audio bars and a floating meeting indicator expose activity. The transcript panel has Stop/Resume. [Transcription](https://docs.granola.ai/help-center/taking-notes/transcription) | App must be running on the device; web viewing cannot capture. Opening the app alone does not capture. |
| Stop, resume, long sessions | Manual stop, detected call completion, 15 minutes without new audio, or computer sleep stop capture. Resume appends to the same note after generation. Back-to-back calls can merge if the meeting app retains the microphone. [Transcription](https://docs.granola.ai/help-center/taking-notes/transcription) | No numeric maximum session duration or crash durability guarantee was found in the examined official help pages. macOS auto-end detection requires admin rights. |
| Transcript organization | Panel supports search, whole-transcript copy, and individual chunk copy/deletion. Green/right is microphone; grey/left is system audio. [Transcription](https://docs.granola.ai/help-center/taking-notes/transcription) | Combined system audio cannot isolate individual apps. Audio/video are not retained; prerecorded audio import is unsupported. |
| Speaker attribution | Optional speaker tags use meeting display names; otherwise labels distinguish microphone from system audio. [Speaker tags](https://docs.granola.ai/help-center/taking-notes/speaker-attribution) | Google Meet needs the extension on Mac/Windows; Zoom is Mac-only. Tags are not retroactive. Shared room devices, overlapping speech, and unrelated audio can prevent correct identity attribution. These are not universal acoustic diarization guarantees. |
| Transcript corrections | Official feature-request page says transcript text editing is unavailable. [Feature requests](https://docs.granola.ai/help-center/feature-requests) | Do not confuse deleting a chunk, editing a generated note, or asking chat to correct a name with changing transcript text. |
| Writing notes | Blank editor accepts headings, lists, checkboxes, bold/italic/underline, and JPEG/PNG paste/drop. Rough notes guide what the AI emphasizes; leaving them blank is allowed. [Writing notes](https://docs.granola.ai/help-center/taking-notes/taking-notes-in-granola) | Rich editing support is a documented capability, not evidence that every pasted format or keyboard path works. |
| Enhancement and grounding | Enhancement combines transcript, typed notes, and calendar context. Enhanced notes are directly editable. Raw notes remain accessible. Per-point magnification exposes supporting transcript/raw notes. Regeneration and chat instructions can change structure or detail. [AI-enhanced notes](https://docs.granola.ai/help-center/taking-notes/ai-enhanced-notes) | Manual edits apply to that note, not future meetings. Documentation describes separate raw/enhanced views; the user's preference for one useful document remains authoritative for Meeting Notes. |
| Templates | Built-in and custom templates specify purpose, length/style, and sections. Applying another template regenerates the note. The dedicated guide describes choosing one during a meeting with `/`. [Templates](https://docs.granola.ai/help-center/taking-notes/customise-notes-with-templates) | Desktop only. Organization sharing requires a company email domain. The feature-request page contradicts the during-meeting selection claim; verify installed behavior before asserting it. |
| AI context, edits, history | Chat scopes to one note, selected notes, folder, person/company, or homepage. It can rewrite selected text or named sections. Chat histories are private even when the meeting is shared; threads can be deleted. [Chat](https://docs.granola.ai/help-center/getting-more-from-your-notes/chatting-with-your-meetings) | Basic accesses the last 30 days; Business/Enterprise access full history. Auto model selection is universal, manual model selection paid. Documentation does not specify follow-up context windows, retry preservation, or cancellation guarantees. |
| AI sources and response delivery | The official chat announcement describes inline citations and disclosure of which meetings were consulted. [Chat announcement](https://www.granola.ai/blog/granola-chat-just-got-smarter) The networking guide identifies streaming AI-summary/chat delivery. [Network guide](https://docs.granola.ai/help-center/troubleshooting/network-troubleshooting) | These substantiate product intent, not citation accuracy, actual streaming smoothness, or a measured latency target. Native inspection and synthetic follow-up tests remain necessary. |
| Reusable AI prompts | Recipes save prompts, appear through `/`, and can target single or multiple meetings. They are searchable, editable, remixable, and optionally shareable. [Recipes](https://docs.granola.ai/help-center/getting-more-from-your-notes/recipes) | Static text only; no variables or dynamic substitution. Basic uses Auto. A recipe has one scope type; duplicating is required for both scope types. |
| Calendar and metadata | Google/Outlook calendars supply titles, attendees, date/time and upcoming notes. Additional calendars can be enabled. Related notes match a recurring event ID or exact title. [Calendar sync](https://docs.granola.ai/help-center/getting-started/syncing-your-calendars) | No retroactive notes from old calendar events; no Apple Calendar integration. Calendar availability depends on account/provider permissions. |
| Reminders | Calendar reminders occur one minute before events with at least two attendees; clicking opens the call and note. Ad-hoc mic-use detection offers a take-notes prompt. Notifications and window repositioning can be configured. [Notifications](https://docs.granola.ai/help-center/taking-notes/notifications) | Granola uses its own popup windows, not native macOS notifications. Detection is not automatic permission to capture every call. |

| People, companies, search | Calendar attendees populate searchable people/company records, grouping related notes and scoped chat. [People and companies](https://docs.granola.ai/help-center/people-and-companies) | No manual directory creation; absent/declined calendar attendees may not appear. Exact global keyword-search fields/ranking were not established from these docs. |

Shared web views omit full transcripts; desktop/folder access differs. Recipient plan alone does not grant or deny an owner's shared link. |
| Bulk export | Settings → Profile → Generate CSV emails an export of owned notes in selected workspaces, including title, summary, transcript and basic details. It includes history hidden by the free plan. [Export](https://docs.granola.ai/help-center/sharing/exporting-notes) | **Notes without a summary and deleted notes are excluded.** One export per 24 hours; download expires after 24 hours. Enterprise may disable export. This is not a complete archival-backup guarantee. |
| Failure diagnosis | Troubleshooting distinguishes connection failure from wrong/missing audio. Transcript colors reveal the missing channel. A microphone selector offers Auto or an explicit device. Network checks report affected features and supply a copyable diagnostic report. [Transcription issues](https://docs.granola.ai/help-center/troubleshooting/transcription-issues) | Live connection required. Some Windows meeting apps may not capture the remote side. Current device-selection docs supersede older marketing claims that Granola has no audio menu. |
| Failed generation | Retry uses a fallback connection method; users can regenerate the chosen template and inspect whether a transcript exists. Long meetings can take minutes. [Generation recovery](https://docs.granola.ai/help-center/troubleshooting/notes-not-generating) | Existing transcript is prerequisite; retry cannot reconstruct uncaptured audio. No crash/restart or long-outage replay guarantee is documented here. |
| Lost/deleted work | Missing-note checks cover account/workspace membership and whether capture ever started. Trash supports restore and permanently deletes after 30 days. [Missing notes](https://docs.granola.ai/help-center/troubleshooting/missing-notes), [Trash](https://docs.granola.ai/help-center/taking-notes/deleting-notes) | Permanent deletion cannot be reversed. | Retention settings | Optional transcript retention preserves editable notes but removes regeneration and degrades chat context. Individual changes have a one-week delay before deletion. [Transcript retention](https://docs.granola.ai/help-center/consent-security-privacy/transcript-auto-deletion) | Enterprise retention overrides individuals and can delete immediately. Do not copy automatic deletion into Meeting Notes merely for parity; preservation is an explicit user requirement. |
| Language and vocabulary | Desktop supports multilingual capture, separate English/Auto summary language, and language changes during a meeting. Personal and workspace jargon guide recognition. [Languages](https://docs.granola.ai/help-center/customising-granola/multi-language), [Jargon](https://docs.granola.ai/help-center/customising-granola/customising-transcription) | Changing capture language can briefly pause capture; it cannot alter existing transcript language. Jargon limits: 30 personal, 50 workspace terms. It is recognition guidance, not guaranteed replacement. |
| Onboarding and settings | Google/Microsoft sign-in, calendar metadata access, microphone/system audio permissions, and a two-minute demo teach the core workflow. Profile context informs summaries; preferences expose training opt-out and beta channel. [Setup](https://docs.granola.ai/help-center/getting-started/setting-up-granola-for-the-first-time), [Preferences](https://docs.granola.ai/help-center/customising-granola/profile-and-preferences) | Setup says macOS 14 minimum. Account sign-in and permission gates must be reported as unavailable if not passed during inspection. Do not change the user's preferences for an audit. |

Older-than-30-day notes are stored but hidden in-app. Business adds full history, other integrations, and model selection; Enterprise adds administrative policies. [Plan comparison](https://docs.granola.ai/help-center/managing-your-account/subscriptions-and-billing) | This is current documentation, not a statement about the installed account's plan. No daily count limit does not establish unlimited continuous session duration, guaranteed uptime, or unlimited AI usage. |
| Briefs and external follow-ups | Briefs summarize prior context for external meetings. [Briefs](https://docs.granola.ai/help-center/taking-notes/pre-meeting-briefs), [Follow-up emails](https://docs.granola.ai/help-center/taking-notes/follow-up-emails) | Briefs need Business/Enterprise and Google Calendar. No connectors were enabled or messages sent for this research. |

## Evidence conflicts and unknowns

- **Template timing:** the dedicated [template guide](https://docs.granola.ai/help-center/taking-notes/customise-notes-with-templates) permits during-call selection; [feature requests](https://docs.granola.ai/help-center/feature-requests) still says before/during selection is unavailable. Prefer actual installed behavior and record version/account context.
- **Old chat documentation:** older `help.granola.ai` pages describe a fixed recent-meeting window and a transcript toggle. The current [chat guide](https://docs.granola.ai/help-center/getting-more-from-your-notes/chatting-with-your-meetings) instead describes automatic context handling with history bounded by plan. Do not apply old limits to the installed version without observing them.
- **Audio selection and Windows coverage:** general documentation describes broad system capture, while the current [troubleshooting guide](https://docs.granola.ai/help-center/troubleshooting/transcription-issues) documents device selection and unsupported Windows meeting apps. A broad marketing claim does not prove specific hardware or application behavior.
- **Unestablished:** maximum desktop session length; exact long-offline buffer/replay policy; abrupt-termination checkpoint guarantee; maximum chat context; citation precision; local edit autosave guarantees; global keyword-search ranking. These require targeted synthetic tests or a more specific official statement, and remain unverified in this document.

## Candidate acceptance checks for the product comparison

These are proposed Meeting Notes checks inferred from the evidence, **not Granola test results or new implementation commitments**. Rank them with the actual app/code audit.

1. Recording status identifies capture and transcription separately. During a synthetic network interruption, saved transcript/notes remain readable; pending local audio survives; retry does not duplicate successful chunks or bill them twice. A visible error identifies any unavailable source.
2. Manual notes, generated additions, edits, export and AI context agree on the useful current document. Regeneration preserves user work or offers a reviewable replacement. Failed generation leaves the prior document intact.
3. AI follow-ups resolve earlier references against current saved evidence. Sources remain discreet but open the cited passage. Retry preserves conversation and draft. Navigation, reload, and closing/reopening behave intentionally and are tested.
4. A transcript can be searched by a distinctive phrase without reading an entire long session. Results retain source identity and meaningful time ordering. No participant name is presented as acoustically verified when only a capture channel is known.
5. Search/organization can retrieve a synthetic meeting by title, notes, transcript, and saved metadata. Basic organization remains local and usable without a calendar connection or paid integration.
6. Export/recovery includes drafts, edited notes, successful transcript checkpoints, and failed/incomplete sessions as appropriate; it must not silently omit work merely because summary generation failed.
